# Pathway AI Frontend: agent notes

@AGENTS.md

- Product direction: read `docs/product/MVP_SPEC.md` before any product, data-model or scope work. It is global, program-first (all disciplines, bachelor and master), with sourced data, USER/ADMIN server-side authorization, no invented acceptance probabilities. It is the target, not the current state: the scope rules below stay in force until the PR for the relevant step changes them deliberately. The backend repo keeps a matching copy; do not edit it from here.

- Scope: the primary navigation is exactly Home, Universities, Scholarships and How It Works. Nested pages exist for the program-first flow (`/universities/[slug]`, `/programs/[identifier]`); do not add other top-level routes, dashboards, auth or onboarding without a spec step. Program pages keep "Universities" highlighted in the header.
- Frontend only. No backend code, auth, payments, database clients or paid APIs here. Pages read the Spring Boot API through `src/lib/api` (browser `fetch` to `NEXT_PUBLIC_API_BASE_URL`): `/api/v1/programs[/{identifier}]` and `/api/v1/universities[/{slug}]`. Scholarships have no backend: keep their honest empty state and keep `src/lib/api/scholarships.ts` unused by pages.
- The API contract is owned by the backend repo (README "REST API contract", pinned by its `ProgramApiIT` and `UniversityApiIT`). `src/types/university.ts` and `src/types/program.ts` mirror it exactly: upper-case enums, nullable fields, `temporalStatus`. Never add a field the API does not return. If the contract changes, update the types, `scripts/check-contract.mjs`, `tests/e2e/helpers/api.ts` and the unit tests together, and run `npm run contract:check` against a running backend.
- Presentation rules for facts: unknown reads "Not stated"; every changing fact shows its source and read date; `HISTORICAL` facts are labelled Outdated and never styled as current; `UNKNOWN_YEAR` says the period is not stated; show an Apply button ONLY when the API returns `officialApplicationUrl` (an active verified link), otherwise show the official admissions information link and say no verified application link exists. Never show rankings, admission probabilities, tuition savings or scholarship awards.
- Next.js Cache Components: dynamic routes (`[slug]`, `[identifier]`) need `generateStaticParams` (a placeholder) and any hook that reads the path (`usePathname`, `useParams`, `useSearchParams`) must sit inside `<Suspense>`; the header's nav links do this.
- Never fall back to mock data when the API fails: show `ErrorState`. Unknown stays unknown (no placeholders, no "0").
- No university, scholarship, tuition, deadline, ranking or admission data in the app. Static geography lives in `src/lib/geography.ts`. Test fixtures must be obviously synthetic and stay in `tests/`.
- `NEXT_PUBLIC_*` is public and inlined at build time. Never put a secret in it. Changing it needs a rebuild.
- This is the frontend repository (`YunisSadig/pathway-ai-frontend`). The backend is the separate repository `YunisSadig/pathway-ai-backend`; never modify it from here. Request backend changes as written tasks.
- This repo is independent. The parent `C:\Users\Lenova` contains an unrelated DevHub repo: always confirm `git rev-parse --show-toplevel` ends in `Desktop/pathway-ai-frontend` before staging.
- Product name is exactly "Pathway AI".
- Theme: Light and Dark only in the UI; first visit follows the device preference (next-themes `defaultTheme="system"`).
- Design system: tokens and rules are in `docs/design/design-system.md` (one font, weights ≤700, 8px controls / 12px containers, no surface shadows, ≥14px text, hairline-divided rows instead of cards, `page-container` width). Performance first: no animation libraries or entrance effects, reserve space (`min-h`) for anything that loads, keep client components small. Results are rows, not cards; applied filters are removable chips; a chosen destination collapses to a summary.
- Local checks must use the production server on port 3000 (backend CORS allows only `http://localhost:3000`); measurements on any other port silently measure the error state.
- Detail pages (`/programs/[identifier]`, `/universities/[slug]`): build them from `components/shared/detail-ui.tsx` (`DetailSection`, `DataRows`, `Notice`, `Evidence`, `Missing`) and `SectionNav`. Do not box every fact in a card; one concise notice and a collapsed `Evidence` citation per fact, not repeated warnings. See `docs/engineering/detail-page-design.md`.
- Every visible button or link must work. Omit unfinished features instead of adding placeholders.
- Checks: `npm run check`, `npm run build`, `npm run test:e2e`. E2E intercepts the API in the browser (`tests/e2e/helpers/api.ts`, synthetic fixtures with the real API's filter and paging semantics), so no backend is needed. Playwright reuses a server on port 3100 locally, but that server must have been built with `NEXT_PUBLIC_API_BASE_URL=http://api.pathway.test`, so make sure no stale one is running. In e2e, locate selects with `getByRole("combobox", { name })`: `getByLabel` also matches option text inside other labels.
- Deployment: nothing is deployed. `docs/deployment.md` records the verified hosting options, the Vercel Hobby non-commercial restriction and the steps that need the owner. `.github/workflows/deploy.yml` is inert until `VERCEL_DEPLOY_ENABLED=true`.
- Shell tip: very long Bash heredocs containing apostrophes can fail to parse; write large files with the Write tool.
